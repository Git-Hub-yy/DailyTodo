# DayTodo · 每日待办

一个安卓手机上的待办清单小工具：按天分组记录要做的事，带一个 4×2 的桌面小部件，
打开手机就能看到今天还剩什么没做。完全离线，不需要账号，不联网。

- 软件名称：**每日待办**（英文/工程名：DayTodo）
- 包名：`com.daytodo.app`
- 当前版本：1.2
- 开发语言：Kotlin（原生 Android）

### 使用小提示

- 各家系统的"省电策略"可能会限制后台广播（例如小米的 Greezer 会拦截一部分后台推送），
  极端省电模式下小部件的自动刷新可能被延迟。App 里已经做了三重兜底：
  打开 App 就会刷新、系统每 30 分钟自动刷新一次、跨零点有独立闹钟。
  万一发现没及时更新，进「设置」点一下「立即刷新小部件」即可。
- 小部件目前是 4×2（可以自己拉伸，行数会跟着高度变），背景图用相册里的图片，
  直角铺满（系统小部件不支持给图片切圆角）。

### 已知限制

- 只有中文界面。
- 没有提醒/通知功能（设计如此：打开手机看小部件就行）。
- 暂不支持数据导出/导入，卸载 App 会一起删掉记录。
- 对外分享的安装包是 **debug 签名**的，自己或朋友安装使用没问题；
  如果要上传应用商店或长期正式分发，需要换成正式签名（releases 签名）。

## 3. 技术方案

- **原生 Android（Kotlin）+ App Widget**，不依赖任何第三方在线服务，完全离线可用。
- 数据存本地 SQLite（Room）。两张表：`tasks`（任务）、`completions`（完成记录，历史记录就来自它）。
- 主题用 Material 3 组件 + `AppCompatDelegate` 切换「跟随系统 / 浅色 / 深色」。
- 小部件用 RemoteViews，4×2；点一行直接勾选；跨零点自动刷新；背景图取自 App 内设置。
- 编译配置：`compileSdk 33` / `targetSdk 33` / `minSdk 26`（Android 8.0 及以上）。
- 产物：`dist\DayTodo-debug.apk`，直接安装即可（手机需允许“安装未知来源应用”）。

### 两种完成逻辑怎么落地

- **A 每日打卡型（DAILY_RESET）**：完成记录按「任务 + 日期」逐天保存，所以今天勾了，明天自动回到未完成。
- **B 整段一次性型（SPAN_ONCE）**：整件事只记一条完成记录；勾掉之后，剩余的天数不再出现。

### 任务期限（重复规则）

仅这一天 / 每天 / 指定星期几 / 每隔 N 天 / 每月某日 / 工作日（周一到周五）/ 周末，
都可以再叠加「起始日期」和「结束日期」；A 类还可选择「无限期重复」。

## 9. 小部件"载入窗口小部件时出现问题"的排查与修复

这是手机桌面（MIUI / HyperOS）在**小部件内容加载失败**时给出的提示，不是 App 自己弹的。
通过 USB 连接手机抓取系统日志，定位到了确切原因：

```
E/Launcher.Widget: widget load error
W/AppWidgetHostView: android.view.InflateException:
    Binary XML file line #19 in com.daytodo.app:layout/widget_today:
    Error inflating class android.view.View
Caused by: android.view.InflateException: Class not allowed to be inflated android.view.View
```

**根本原因**：小部件界面用的是系统的 RemoteViews，它只允许使用被标记过的控件
（TextView、ImageView、LinearLayout、FrameLayout 等），而 **`android.view.View` 这个基础类不在允许名单里**。
我在小部件里用 `<View>` 做了一层"背景暗化遮罩"，桌面一加载就抛异常，于是显示系统提示。

**修复**：把 `<View>` 换成 `FrameLayout`（允许的容器），其余逻辑不变。

验证：用 adb 把 1.2 版直接装到手机（Redmi K60 / HyperOS）上，日志中不再出现 inflate 报错，
桌面小部件正常显示「10月11日 星期日 / 未完成 1 / 共 1 / ○ 快手极速版签到」。

顺带在排查过程中一起处理掉的其他隐患：

| 可能原因 | 处理方式 |
| --- | --- |
| 小部件布局里用了**矢量图标**，小米桌面加载这类资源容易失败 | 已全部换成普通文字符号（○ / ●），小部件里不再有任何矢量图 |
| 小部件**更新太晚**：原来是丢一个后台任务就返回，小米桌面对首次加载有超时限制 | 改成收到请求后**立刻更新完再返回**（并加了超时保护），不再依赖后台线程 |
| 内容一旦构建失败就没有兜底，桌面只能显示系统报错 | 加了兜底内容：即使构建失败也送去一个"正在载入…"界面 |
| `previewLayout`、`targetCellWidth/Height` 这两个可选配置在某些桌面版本上有兼容问题 | 已移除，改用 `minWidth/minHeight`（250dp × 110dp，仍然是 4×2） |
| 只靠零点闹钟刷新，一旦被系统拦住就长期不更新 | 打开系统自带的定期刷新（30 分钟一次）作为兜底 |

另外在「设置」里新增了「立即刷新小部件」按钮，万一桌面显示异常，点一下就能强制重刷。

升级后不需要重新添加小部件，安装完成会自动刷新一次（旧小部件实例也能恢复正常）。

| 界面语言 | 全中文 |
| 提醒通知 | 未做（按需求不需要），小部件打开手机即可看到 |

### 已知的小限制

- 自定义背景图是直角铺满的（系统小部件不支持给图片切圆角）。
- 小部件的行数会跟着小部件高度自动变化：把 4×2 拉高一点能多显示几行。
- 列表排序规则是固定的（未完成在上、已完成沉底），暂时不支持手动拖动排序。
- 历史记录记录的是"完成"，不记录"删除/修改"这类操作。

## 7. 怎么装到手机

1. 把 `D:\chatgpt\DayTodo\dist\DayTodo-debug.apk` 传到手机（微信文件传输助手、数据线拷贝都行）。
2. 在手机上点开这个文件安装。如果弹出"禁止安装未知来源应用"，在弹窗里选"允许本次安装 / 允许此来源"。

## 8. 怎么自己编译（给想改代码的人）

环境要求：

- JDK 11（更高版本也可以，但需相应调整 Gradle 版本）
- Android SDK：`platforms;android-33`、`build-tools;33.0.2`
- 首次编译需要联网下载依赖

步骤：

1. 在 `project\` 目录下新建 `local.properties`，写上你自己的 SDK 路径，例如：

   ```
   sdk.dir=D\:\\Android\\Sdk
   ```

   （这个文件跟具体电脑有关，所以没有放进仓库。）

2. 在 `project\` 目录下执行：

   ```
   gradlew.bat assembleDebug
   ```

3. 产物在 `project\app\build\outputs\apk\debug\app-debug.apk`。

仓库里的 `gradle\wrapper\gradle-wrapper.properties` 把 Gradle 下载地址指向了国内镜像
（华为云），在国内会快很多；如果你在海外，可以改回 `services.gradle.org`。

运行单元测试：

```
gradlew.bat testDebugUnitTest
```
